### 2026-09-14 · M3-02a · `SkillSpec`, `TriggerSpec`, `SkillTreeSpec`: the tree as data

**Built:** **the tree exists as data, and a node can now carry the effect M3-05 built.** `SkillSpec` is CH §4's four kinds with the effects taking it puts into force; `ActiveSpec` is what an Active is when it fires — authored base cooldown, trigger, cast effects — and **rule 1 is checked in both directions, unlike `EnemySpec`**: an Active without its block is a skill that cannot fire, a block on a Passive is a cooldown nothing will run, and `ParentId` is the same rule again. `TriggerSpec` is CC §6.4's condition as one or two ANDed `TriggerClause`es over the nine `CombatBlackboard` fields — **ADR-0005's "pure predicates, carried by the `SkillSpec` as data" made authorable**, because a lambda cannot come out of an asset and an enum-and-a-threshold can. `SkillTreeSpec` is three branches of tiers of ids with `TryLocate` as a dictionary built once. `ContentCatalog` gained the fourth and fifth kinds through the same `Index`, plus **one second index nothing else has** — `TryGetTreeFor(characterId)`, the door a run actually uses.
**Deviations:** three, all in the spec's *As built*. The one that changes a decision is **rule 6's own parenthetical, which is wrong and had to be corrected to be honoured.**
**Learned:** **AR §18.3's NaN spelling is about which side of a predicate NaN lands on, and the `!` is not part of the rule.** Rule 6 prescribed `!(value < threshold)`; applied to `AtLeast` — the only comparison a `!` could belong to — `!(NaN < 0.6)` is **true**, so a broken blackboard would have satisfied every `AtLeast` clause the player owns and fired every active at once, which is the exact failure the rule's own sentence forbids. The `!` in AR §18.3's `!(value > 0f)` is there because a **guard** wants NaN on the *throw* side; a predicate wants it on the *false* side and needs no `!` at all. Both comparisons are written out rather than derived from each other, and `Trigger_NaNFieldFails` — which demanded `false` all along — is what proved the parenthetical rather than the code was the bug → **AR §18.3**, as a second sentence on the existing row. **`Core/Content` stopped being a leaf**: it held zero `using Soulvail.*` before this task and now names `Core.Combat` and `Core.Effects`, which makes `Content ↔ Combat` a namespace cycle — harmless today, and it would block AR §5's own *"split into separate assemblies only if compile times demand it"* → parking lot, and **AR §5 needs no row edited**, which is the answer the `XpCurve` precedent was checked against rather than assumed from. **A test written against reflection cannot drift from the thing it checks:** `Trigger_EveryFieldReads` walks `Enum.GetValues` and looks each member up on `CombatBlackboard` *by name*, so a field wired to the wrong one reads 0 and fails, a field wired to nothing throws out of the loud `default`, and a member naming no field fails the first assertion — three failure modes, no hand-kept table → spent (stays here).

# FX-01 — No banked points past the level budget

**Size:** S · **Depends on:** — · **Branch:** `dev`
**Design refs:** LV-02a rule 6, LV-02d (in `git log`)

## Goal

A resumed run never holds more unspent points than its level earns and its taken ranks have not spent.

Owner playtest, 2026-11-05: level 30, Marksman full, 6 points banked. Cause: a pre-cap save (say level 36, 29 taken, 6 pending) comes back at 30 with its 6 points kept (`LevelTracker.Restore`, LV-02a rule 6), and `RunSession`'s resume refund adds removed ranks on top.

## Public API

No new members. `LevelTracker.Restore(level, xp, pendingLevelUps)` is the clamp's door.

## Behaviour

1. On resume, once the tree has restored (and refunded), pending = `min(pending, max(0, Level − 1 − tree.TakenIds.Count))`, using the **capped** level. A class with no tree is untouched.
2. A save inside the budget keeps every point.
3. A save above the cap still comes back at the cap (LV-02a), now with rule 1's points.
4. The existing "saved picks do not add up" refusal is unchanged: it still reads the saved level, so no save that loaded before is refused now.
5. The clamp publishes nothing (resume is silent).

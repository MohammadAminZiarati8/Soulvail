# FX-03 — Auto-aim skips enemies behind cover

**Size:** M · **Depends on:** — · **Branch:** `dev`
**Design refs:** CC §3.1, AR §18.2, GD §7.2

## Goal

The Ranger never auto-targets, and so never shoots, an enemy that a rock or pillar hides from them.

Owner playtest, 2026-11-05: basic attacks pass through rocks. Core holds no walls. `LineOfSightSense` already fills `EnemySense.HasLineOfSight` every frame, but `PlayerCombat`'s candidate builder never reads it.

A new field rather than reading `HasLineOfSight` directly: its default is false, and every existing fixture would turn untargetable.

## Public API

```csharp
// EnemySense
public bool BehindCover;
// EnemyBlackboard
public bool IsBehindCover;
```

## Behaviour

1. A candidate whose blackboard says `IsBehindCover` is left out of targeting (not marked invulnerable; JG-22a rule 5's reason).
2. With the nearest enemy covered and another visible, the visible one is the target.
3. With every enemy covered, there is no target and no basic attack starts.
4. An enemy that comes out of cover is a candidate on the next targeting decision.
5. A freshly spawned enemy (no sense yet) is targetable.
6. The candidate builder allocates nothing.
7. With no sight sense wired (`_sight == null`), nothing is covered.

## Manual verification (Editor / device)

1. **[Editor]** Stand so a rock hides an enemy: the Ranger turns to the visible enemy, or holds fire if none.
2. **[Editor]** Step clear: firing resumes within a beat.

## Out of scope

- Stopping arrows already in flight at cover (needs a cover fact; say so in *As built*).
- Killshot, Volley and Rain of Arrows: they ignore cover, unchanged.
- Enemy line-of-sight behaviour.

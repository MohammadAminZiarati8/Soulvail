# UI-09d — A soft glow for the payout

**Size:** S · **Depends on:** UI-09c · **Branch:** none — committed on `dev` (owner, 2026-10-14)
**Design refs:** GD §16.4 · **Ledger rows:** none — promotes the [parking-lot](../ROADMAP.md#parking-lot) line on `Glow_Soft`'s hard rim

## Goal

The Run-end payout glows with a sprite of its own that fades to nothing at its edge, so no box shows on the dark pill; the HUD's `Glow_Soft` is unchanged.

## Why a new sprite

UI-09c tinted `Glow_Soft`, and its alpha drops from 51/255 to 0 between two neighbouring pixels at its edge, a step that shows as a square edge around the shard figure. Recutting `Glow_Soft` would change the glow behind a ready skill cell on the HUD too, and `HudArtTests` pins it byte for byte to the UI_v2 cut. `UI_v5/2.jpg`'s glow burst is not usable, because its halo fades into the magenta key (UI-09a). **So the payout gets a radial glow generated by a script**, not cut from a sheet: `Soulvail_GeminiSamples/UI_v5/make_glow.py` writes `UI_v5/png/RunEnd_Glow.png`, the same folder the cutter writes to.

## Public API

None. The presenter's fields and layout are unchanged.

## Behaviour

1. **`RunEnd_Glow` is 256 × 256, white, with alpha `round(255 · (1 − r²)²)`** for `r < 1` and 0 beyond, where `r` is a pixel centre's distance from the image centre over 128 px. The asset is `make_glow.py`'s output byte for byte.
2. **It fades to zero at its edge, with no step:** every pixel at `r ≥ 1` has alpha 0, including all four edges; walking out along the centre row and column, alpha never rises, and no two neighbouring pixels differ by more than 4/255. (`Glow_Soft` fails this: a 51 → 0 step at its edge.)
3. **It imports like the other Run-end pieces**: a single full-rect UI sprite, 100 PPU, clamped, bilinear, alpha is transparency, no mipmaps, no border, ASTC 4×4 on Android.
4. **The payout glow wears `RunEnd_Glow`.** Everything else in UI-09c rule 5 stays: tinted `Palette.Essence` at alpha 0.6, twice the row's height, centred on the figure's text, behind the figure and above the pill.
5. **`RunEnd/` holds five pieces**: the four from UI-09a and the glow.
6. **`Glow_Soft` and the HUD are untouched**; `HudArt_IsByteForByteTheCut` already pins the sprite, so no new row.

## As built

**2026-10-17.** As specified, in the two files plus the small edits and the ripple.

- **The curve's steepest neighbouring step is 4/255**, at `r ≈ 0.58`, which is where rule 2's bound comes from; `Glow_Soft`'s is 51 → 0 at its last opaque pixel, so `RunEndArt_Glow_FadesToZeroAtItsEdge` would fail on it. The last nonzero pixel along an axis is 1/255.
- **The `.meta` is `Glow_Soft.png.meta`** with a new guid, the sprite renamed and resized to 256, and new sprite ids; it already carried the ASTC 4×4 Android override. Unity imported it without rewriting it.
- **`RunEndArtTests` gained a shared `AssertUiSprite` and `Pixels`**; the glow stays out of `PiecePaths`, because `RunEndArt_NoMagentaLeft` refuses partial alpha away from an edge, which a glow is everywhere.
- **No render was taken**; the pixel rows are the evidence, and the owner's look is the manual step.
